# ADR-0003: Стратегия конфигурации AI-агентов (Канонический AGENTS.md + Зеркала для редакторов)

> **Статус:** Принято  
> **Дата:** 2026-09-30  
> **Теги:** #adr #architecture #agents #tooling  

---

## 1. Контекст и проблема
Современная экосистема инструментов для агентной разработки сильно фрагментирована:
* **AGENTS.md:** Общепринятый открытый стандарт (поддерживается Aider, OpenHands, Antigravity и рядом CLI-агентов).
* **VS Code Cline & Roo Code:** Используют файл `.clinerules` в корне проекта.
* **Claude Code CLI:** Использует файл `CLAUDE.md`.
* **Cursor IDE:** Использует файл `.cursorrules` или `.cursor/rules/*.mdc`.
* **GitHub Copilot:** Читает файл `.github/copilot-instructions.md`.

Если создать правила только под один редактор, инструмент потеряет кроссплатформенность и не подойдет командам с разным инструментарием. Если же копировать один и тот же многостраничный текст во все файлы, возникнет дублирование и риск расхождения инструкций при обновлениях.

## 2. Решение
Принята гибридная стратегия **«Канонический стандарт + Адаптеры редакторов»**:
1. **Единый источник правды (Single Source of Truth):** Корневой файл `AGENTS.md`. В нем детально зафиксированы регламент базы знаний `docs/`, 3 строгих режима работы (Планирование → ТЗ → Реализация), запрет на самовольное изменение кода, принципы Permalinks и Regression-First, а также команды сборки и верификации для выбранного технологического стека.
2. **Легковесные зеркала-адаптеры:** При выборе опции `--agent all` (или конкретного редактора) инсталлятор генерирует:
   * `.clinerules` (для Cline / Roo Code) — краткий жесткий промпт, требующий чтения `AGENTS.md` и блокирующий редактирование кода в Режимах 1 и 2.
   * `CLAUDE.md` (для Claude Code) — сводка команд `Build`, `Test`, `Lint KB` и ссылка на регламент.
   * `.cursorrules` (для Cursor) — контекстные правила поведения модели.
   * `.github/copilot-instructions.md` (для GitHub Copilot) — системный контекст для чата и кодогенерации.

## 3. Рассмотренные и отвергнутые варианты (Considered & Rejected Alternatives)
* **[Отклонено] Генерация исключительно `AGENTS.md`:**
  * *Причины отклонения:* На момент 2026 года расширения VS Code (такие как Cline) и Cursor по умолчанию ищут свои проприетарные конфигурационные файлы (`.clinerules`, `.cursorrules`). Без их создания агент может проигнорировать `AGENTS.md` при первом старте диалога.
* **[Отклонено] Использование файловых симлинков (Symlinks) на `AGENTS.md`:**
  * *Причины отклонения:* Создание символических ссылок в Windows требует прав администратора или включенного Developer Mode (`SeCreateSymbolicLinkPrivilege`). На многих машинах пользователей вызов `os.symlink` падает с `OSError: [WinError 1314] A required privilege is not held by the client`.
* **[Отклонено] Полное дублирование текста `AGENTS.md` во все 5 файлов:**
  * *Причины отклонения:* Замусоривает кодовую базу, усложняет чтение и создает высокий риск рассинхронизации правил при внесении правок пользователем.

## 4. Обоснование и последствия

### Плюсы:
* **Максимальная совместимость:** Любой агент (будь то Cline в VS Code, Cursor, Copilot или Claude Code в терминале) мгновенно подхватывает правила без ручной настройки.
* **Чистота и прозрачность:** Адаптеры лаконичны и явно ссылаются на канонический `AGENTS.md` и `docs/Onboarding.md`.

### Минусы и риски:
* **Потенциальное появление новых расширений:** Появление новых агентов (например, Windsurf) потребует добавления соответствующих адаптеров (запланировано в Фазе 2).
