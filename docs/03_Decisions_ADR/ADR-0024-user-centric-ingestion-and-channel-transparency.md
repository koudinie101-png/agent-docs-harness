# ADR-0024: Архитектура прозрачности каналов обратной связи, автоопределения репозитория и диагностического статуса

## 1. Контекст и проблема

Внедренный в Фазе 12 механизм сбора входящей обратной связи (`scripts/kb_ingest.py` и процедура Режима 2C `/kb-triage`) страдает от проблемы «черного ящика»:
1. **Немые пропуски каналов (Silent Skipping):** Если переменные окружения `GITHUB_REPOSITORY` или `FEEDBACK_IMAP_*` не заданы явно, скрипт молча пропускает запросы и выводит сообщение `OK: Ingest checked (0 new items, 0 skipped)`, создавая иллюзию отсутствия новых обращений.
2. **Игнорирование локального Git-контекста:** В репозитории почти всегда присутствует `git remote origin`, откуда можно автоматически получить имя репозитория `owner/repo`, однако текущий код требует ручной конфигурации.
3. **Жесткий хардкод метки `needs-triage`:** Issues, созданные без указанной метки (например, напрямую через веб-интерфейс GitHub без шаблонных форм), полностью игнорируются при сборе.
4. **Отсутствие диагностического статуса:** Нет возможности быстро оценить состояние источников, наличие токена авторизации, лимиты API и количество обращений в буфере `Inbox/`.

## 2. Решение

Принята комплексная архитектура **User-Centric Ingestion & Channel Transparency**:

### 2.1. Zero-Deps автодетект GitHub репозитория
В `scripts/kb_ingest.py` внедряется функция автоматического определения репозитория `detect_github_repo()` через стандартную утилиту `git config --get remote.origin.url` с парсингом HTTPS и SSH URL. Ручная переменная окружения `GITHUB_REPOSITORY` сохраняет статус опционального переопределения (override).

### 2.2. Запрет «немых пропусков» (Channel Transparency Invariant)
Если канал активирован (флагами `--github`, `--email` или по умолчанию), но его конфигурация неполна или недоступна:
* Скрипт **обязан** вывести явное предупреждение `⚠️ Warning: [Канал] пропущен: [Причина и инструкция по настройке]`.
* Тихие пропуски каналов без уведомления категорически запрещаются.
* Для GitHub при отсутствии `GITHUB_TOKEN` выводится информационная плашка об использовании анонимного режима (лимит 60 req/h) и способе переключения на 5000 req/h через файл `.env.local`.

### 2.3. Гибкие фильтры инжеста (`--label` и `--all-open`)
* Вводится флаг `--label <NAME>` для фильтрации по произвольной метке (значение по умолчанию: `needs-triage` для сохранения обратной совместимости).
* Вводится флаг `--all-open`, отключающий фильтрацию по меткам и собирающий все открытые issues репозитория (за исключением Pull Requests).

### 2.4. Диагностический режим статуса (`--status`)
Вводится команда `python scripts/kb_ingest.py --status`, выводящая наглядную текстовую сводку:
* Состояние канала GitHub (репозиторий, статус токена, текущий фильтр меток, курсор смещения из `.inbox_state.json`);
* Состояние канала Email (хост, логин, статус конфигурации, курсор UID);
* Статистика буфера `docs/02_Tasks/Inbox/` (количество файлов с `status: new`, `processed`, `rejected`).

### 2.5. Диагностический фидбек в Режиме 2C (`/kb-triage`)
В процедуре скилла `/kb-triage` при отсутствии необработанных тикетов (`status: new`) агент формирует диагностический отчет на основе `--status`, подтверждая пользователю факт успешного опроса конкретных источников.

## 3. Отвергнутые варианты (Rejected Alternatives)

* ❌ **Аварийное завершение с ошибкой (Exit code 1) при отсутствии конфигурации:**  
  *Причина отказа:* Ломает автономные сценарии локального использования (например, быстрое сохранение сниппетов `--paste` или запуск в проектах без внешних сервисов). Заменено на неблокирующие предупреждения (warnings).
* ❌ **Использование внешних SDK (PyGithub, GitPython):**  
  *Причина отказа:* Нарушает фундаментальный принцип [[ADR-0001-zero-dependencies-python-stdlib|ADR-0001]] (Zero Dependencies на стандартной библиотеке Python 3).
* ❌ **Отказ от фильтрации меток по умолчанию:**  
  *Причина отказа:* Сбор всех подряд issues в крупных репозиториях приведет к засорению буфера закрытыми обсуждениями и сторонними тикетами. Флаг `--all-open` сделан явным опциональным выбором.

## 4. Последствия

### Плюсы:
1. **Zero Configuration DX:** Инжест работает «из коробки» сразу после клонирования репозитория с GitHub.
2. **Исключение иллюзии «пустого инбокса»:** Пользователь всегда видит причину, по которой тикеты не были собраны.
3. **Универсальность:** Поддержка репозиториев с любыми соглашениями по меткам через `--label` и `--all-open`.
4. **Прозрачность:** Наглядный статус источников через флаг `--status` и интеграция в `/kb-triage`.

### Минусы / Компромиссы:
1. Зависимость от доступности команды `git` в операционной системе для автоматического детекта (при отсутствии git сохраняется возможность явного указания через `GITHUB_REPOSITORY`).
