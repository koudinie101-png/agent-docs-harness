# ADR-0002: Монолитная сборка инсталлятора через Self-Contained Bundle (zlib + Base64)

> **Статус:** Принято  
> **Дата:** 2026-09-30  
> **Теги:** #adr #architecture #bundling #packaging  

---

## 1. Контекст и проблема
При запуске инсталлятора через конвейер терминала (`curl -sSL .../install.py | python3`) у скрипта нет доступа к локальным файлам репозитория. При этом инсталлятор обязан развернуть в целевом проекте:
* 12 эталонных шаблонов Markdown (`00_Templates/`).
* Конфигурационный файл цветовой схемы Obsidian Graph (`.obsidian/graph.json`).
* Автономный скрипт линтера базы знаний (`scripts/kb_lint.py`).

Необходимо решить, каким образом эти артефакты доставляются в скрипт и как обеспечивается их синхронизация с исходным кодом репозитория.

## 2. Решение
Принята архитектура **Self-Contained Bundling**:
1. В исходном репозитории шаблоны хранятся как чистые, читаемые Markdown-файлы в каталоге `templates/`, а линтер — в `scripts/kb_lint.py`.
2. Специальный скрипт сборщика `scripts/build_installer.py` считывает эти файлы, упаковывает их в словарь JSON, сжимает с помощью алгоритма `zlib` (уровень 9) и кодирует в строку `base64`.
3. Результирующая компактная строка внедряется в тело `install.py` между маркерами:
   ```python
   # --- BEGIN_EMBEDDED_ASSETS ---
   EMBEDDED_ASSETS_B64 = "..."
   # --- END_EMBEDDED_ASSETS ---
   ```
4. При запуске `install.py` распаковывает бандл за 5 миллисекунд прямо в оперативной памяти и производит параметризацию под выбранный пользователем технологический стек.
5. Для локальной разработки в `install.py` сохранен fallback: если бандл пуст, скрипт автоматически читает файлы с диска.

## 3. Рассмотренные и отвергнутые варианты (Considered & Rejected Alternatives)
* **[Отклонено] Динамическая загрузка каждого файла по HTTP из raw.githubusercontent.com:**
  * *Причины отклонения:* Требует активного интернет-соединения в течение всей работы инсталлятора, подвержено сетевым сбоям, падает при корпоративных прокси и упирается в rate-limit GitHub API. Увеличивает время установки с сотен миллисекунд до нескольких секунд.
* **[Отклонено] Обязательное клонирование репозитория (`git clone`):**
  * *Причины отклонения:* Создает лишний мусор на диске пользователя, требует от пользователя ручного удаления клонированного репозитория и ломает концепцию установки «в одну строчку».
* **[Отклонено] Хранение сырого текста шаблонов как многострочных строк Python (Triple-quoted strings):**
  * *Причины отклонения:* Высокий риск синтаксических конфликтов (в шаблонах и коде `kb_lint.py` содержатся тройные кавычки, регулярные выражения, спецсимволы экранирования и разные переводы строк CRLF/LF). Кроме того, скрипт раздувается до ~50 КБ, тогда как сжатие `zlib` сокращает полезную нагрузку до ~18 КБ.

## 4. Обоснование и последствия

### Плюсы:
* **Абсолютная автономность:** `install.py` является единым неделимым файлом. Его можно сохранить на флешку, передать по сети, сохранить локально и запустить в полностью изолированной среде (air-gapped environment).
* **Сжатие данных:** Размер передаваемого по сети скрипта сокращается более чем в 2 раза (коэффициент сжатия 55%).
* **Удобство разработки:** Разработчики `agent-docs-harness` редактируют шаблоны как обычные Markdown-файлы с подсветкой синтаксиса и автодополнением в IDE, не работая с экранированными строками вручную.

### Минусы и риски:
* **Необходимость этапа компиляции бандла:** При изменении шаблонов в `templates/` или линтера в `scripts/` требуется запуск `python scripts/build_installer.py` (автоматизировано через unit-тесты).
