# ADR-0006: Отказ от встроенного генератора PDF-отчетов для руководства

> **Статус:** Отклонено  
> **Дата:** 2026-10-01  
> **Теги:** #adr #architecture #rejected #reporting #tooling  

---

> [!NOTE]
> **Отказное решение (`status: rejected`):** Данное решение фиксирует аргументированный отказ от разработки специализированного скрипта генерации PDF/Executive отчетов в пользу возможностей самих AI-агентов и нативного экспорта в Markdown/Obsidian.

## 1. Контекст и проблема
В бэклоге гипотез рассматривалось предложение разработки встроенной CLI-утилиты для автоматической сборки дайджестов прогресса проекта:
* Парсинг выполненных вех из [[../02_Tasks/Roadmap|Roadmap.md]], закрытых задач из [[../02_Tasks/Kanban|Kanban.md]] и последних записей из [[../Devlog|Devlog.md]].
* Генерация форматированного PDF-документа или презентабельного отчета для демонстрации стейкхолдерам и руководству.
* Цель предложения: упростить процесс составления регулярной отчетности о ходе разработки.

## 2. Решение
**Решение: ПОЛНОСТЬЮ ОТКЛОНИТЬ разработку встроенного Python-генератора PDF-отчетов.**

1. **AI-агенты уже превосходно решают эту задачу:** В агентной среде разработчику достаточно дать команду агенту: *«Сделай Executive Summary по Roadmap и Devlog за прошедшие 2 недели для презентации руководству»*. Агент мгновенно агрегирует факты, убирает технический шум и формирует отчет в любом требуемом формате (Markdown, HTML, таблица).
2. **Экспорт силами редакторов:** Для конвертации в PDF используются штатные средства: кнопка «Export to PDF» в Obsidian или расширения Markdown PDF в VS Code / Cursor, которые используют готовый Chromium-движок без необходимости поддержания собственного рендерера.

## 3. Рассмотренные и отвергнутые варианты (Considered & Rejected Alternatives)

* **[Отклонено] Включение PDF-библиотек (ReportLab, WeasyPrint, FPDF2):**
  * *Причины отклонения:* Прямое нарушение фундаментального принципа [[ADR-0001-zero-dependencies-python-stdlib|ADR-0001 (Zero Dependencies)]]. WeasyPrint требует системных библиотек Pango/cairo, которые сложно ставить на Windows и macOS. ReportLab имеет огромный вес и не входит в Python stdlib.
* **[Отклонено] Самописный легковесный PDF-генератор на чистом Python stdlib:**
  * *Причины отклонения:* Спецификация PDF крайне сложна. Поддержка кириллических шрифтов (Unicode/TrueType embedding), автопереноса строк, пагинации и таблиц на чистом Python без зависимостей требует тысяч строк хрупкого кода, не имеющего отношения к ключевой ценности проекта.
* **[Отклонено] Интеграция с внешними CLI-утилитами (Pandoc / Typst):**
  * *Причины отклонения:* Требует от пользователя установки внешних тяжелых пакетов (Pandoc, LaTeX или Typst), что создает точки отказа и несовместимость окружений.

## 4. Обоснование и последствия

### Плюсы отказа:
* **Отсутствие раздувания кодовой базы:** Проект не берет на себя обслуживание сложного рендерера документов.
* **Максимальная гибкость отчетов:** AI-агент адаптирует стиль отчета под любую аудиторию (для технического лида, для инвестора, для маркетологов), в отличие от жестко зашитого шаблона в Python-скрипте.

### Альтернативный рекомендуемый рабочий процесс:
* Разработчик или менеджер обращается к агенту:
  > *«Проанализируй docs/02_Tasks/Roadmap.md и docs/Devlog.md. Подготовь лаконичный отчет о закрытых вехах, текущих рисках и планах на следующую фазу в формате Markdown»*.
* Полученный документ при необходимости распечатывается через экспорт Obsidian или IDE.
