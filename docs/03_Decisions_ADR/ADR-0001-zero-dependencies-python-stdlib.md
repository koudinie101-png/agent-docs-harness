# ADR-0001: Архитектура Zero Dependencies на стандартной библиотеке Python 3

> **Статус:** Принято  
> **Дата:** 2026-09-30  
> **Теги:** #adr #architecture #dependencies #python  

---

## 1. Контекст и проблема
Цель проекта `agent-docs-harness` — дать разработчику возможность мгновенно развернуть процессы Docs-as-Code и дисциплину AI-агентов в любом проекте одной командой терминала:
```bash
curl -sSL https://raw.githubusercontent.com/koudinie101-png/agent-docs-harness/main/install.py | python3
```
Для успеха этой утилиты критически важно устранить любые барьеры входа:
* Разработчик может не иметь прав администратора или настроенного виртуального окружения (`venv`).
* Во многих средах (особенно на macOS, где системный Python управляется ОС) вызов `pip install` по умолчанию блокируется защитой PEP 668 (`externally-managed-environment`).
* Установка внешних библиотек (PyYAML, requests, rich, click) замедляет запуск, создает риски несовместимости версий и требует доступа к PyPI.

## 2. Решение
Принято решение реализовать всю функциональность инсталлятора `install.py`, сборщика `scripts/build_installer.py` и линтера базы знаний `scripts/kb_lint.py` **исключительно на базе стандартной библиотеки Python 3.8+ (Zero Dependencies)**:
* Файловые операции и пути: `pathlib.Path`, `os`, `shutil`.
* Сериализация и парсинг: `json`, `re`.
* Сжатие и кодирование полезной нагрузки: `zlib`, `base64`.
* CLI аргументы: `argparse`.
* Интерактивный диалог: встроенные механизмы `input()`, TTY-детект через `sys.stdin.isatty()` и прямое открытие `/dev/tty` (macOS/Linux) или `CONIN$` (Windows).
* Процессы и Git: `subprocess`.

## 3. Рассмотренные и отвергнутые варианты (Considered & Rejected Alternatives)
* **[Отклонено] Публикация пакета на PyPI (`pip install agent-docs-harness`):**
  * *Причины отклонения:* Требует наличия активированного venv или запуска с флагом `--break-system-packages` на современных macOS/Linux (PEP 668). Значительно усложняет сценарий использования для разработчиков, пишущих на Swift, Go или Node.js, у которых в проекте нет Python-окружения.
* **[Отклонено] Использование богатых библиотек форматирования (Rich / Typer / Click):**
  * *Причины отклонения:* Добавляет транзитивные зависимости. Стандартный `argparse` и аккуратная ANSI-разметка в стандартном `print()` полностью закрывают задачи красивого CLI-интерфейса без накладных расходов.
* **[Отклонено] Написание инсталлятора на Bash / Shell Script:**
  * *Причины отклонения:* Shell-скрипты плохо переносимы на Windows (требуют Git Bash / WSL / MSYS2), подвержены ошибкам парсинга путей с пробелами и спецсимволами, а также не позволяют реализовать надежную логику валидации ссылок и сжатия бандла.

## 4. Обоснование и последствия

### Плюсы:
* **Мгновенный старт:** Работает из коробки на macOS, Linux и Windows при наличии любого Python 3.8+.
* **100% изоляция:** Не оставляет следов в глобальном Python-окружении пользователя, не требует `pip`.
* **Долговечность и стабильность:** Стандартная библиотека Python гарантирует обратную совместимость на годы вперед.

### Минусы и риски:
* **Необходимость реализации собственной логики валидации:** Отказ от `PyYAML` потребовал написания легковесного парсера заголовков YAML frontmatter в `scripts/kb_lint.py`.
* **Ограничение графических возможностей:** Отсутствие сложных интерактивных TUI-элементов (спиннеры, прогресс-бары), что с лихвой компенсируется скоростью работы (установка занимает менее 1 секунды).
