## 1. Контекст, проблема и проверяемые гипотезы

### Проблема
Разработчики используют кардинально разные среды для парного программирования с AI:
1. **Специализированные IDE нового поколения:** Google Antigravity, Cursor IDE, Windsurf (Codeium).
2. **Плагины и расширения для VS Code / JetBrains:** Cline, Roo Code, GitHub Copilot, Continue.dev.
3. **Автономные терминальные CLI-агенты:** Claude Code CLI, Aider.
4. **Разнообразие моделей:** от облачных флагманов (Claude 3.7 Sonnet, Gemini 2.0 Pro, GPT-4o) до мощных открытых локальных моделей (**Qwen 2.5 Coder**, DeepSeek R1/V3), работающих через Ollama или vLLM с полной изоляцией исходного кода.

Каждая среда имеет свои точки входа для системных промптов (`GEMINI.md`, `AGENTS.md`, `.clinerules`, `CLAUDE.md`, `.cursorrules`, `.windsurfrules`, `.github/copilot-instructions.md`), свои особенности работы со скиллами (MCP, Custom Tools, Subagents) и разную чувствительность к языку общения.

### Проверяемые гипотезы
* **Гипотеза 1:** Единый структурированный корень правил (`AGENTS.md`) в комбинации со специализированными адаптерами-зеркалами обеспечивает надежное соблюдение Docs-as-Code во всех средах.
* **Гипотеза 2:** Открытые модели, в частности **Qwen 2.5 Coder** (32B / 14B / 7B), при наличии строгих 3-режимных инструкций и четких шаблонов задач (`TASK-XXX`) работают на уровне топовых коммерческих моделей, гарантируя отсутствие утечки коммерческого кода.
* **Гипотеза 3:** Явное указание предпочтительного языка документации (`doc_lang`) в системных правилах предотвращает спонтанный переход агентов на английский язык при ведении русскоязычных проектов.

## 2. Анализ сред разработки и точек входа правил

### 2.1. Google Antigravity & Gemini CLI
* **Точка входа:** Корневой файл `GEMINI.md` и универсальный `AGENTS.md`. Каталог конфигураций `.gemini/` (глобально `~/.gemini/antigravity`).
* **Особенности рантайма:**
  * Поддержка нативной подсистемы скиллов (`skills/`, файлы `SKILL.md` с YAML frontmatter).
  * Поддержка субагентов (`invoke_subagent`, `self`, `research`) с изолированными контекстами.
  * Интерактивные UI-виджеты и сессионные артефакты.
  * Модели: Gemini 2.0 Pro / Flash, Gemini 1.5 Pro (контекст до 2M токенов).

### 2.2. VS Code: Cline & Roo Code
* **Точка входа:** Корневой файл `.clinerules`.
* **Особенности рантайма:**
  * Протокол Model Context Protocol (MCP) для подключения внешних инструментов.
  * Жесткое разделение режимов (Plan Mode / Act Mode). Наш Режим 1 и Режим 2 идеально ложатся на Plan Mode, а Режим 3 — на Act Mode.
  * Поддерживает любые модели через OpenRouter, Anthropic, OpenAI, Ollama (Qwen 2.5 Coder).

### 2.3. Anthropic Claude Code CLI
* **Точка входа:** Корневой файл `CLAUDE.md`.
* **Особенности рантайма:**
  * Работает прямо в терминале, выполняет bash-команды напрямую.
  * Контекст очищается/компактизируется (`/compact`), поэтому краткие и емкие правила в `CLAUDE.md` со ссылкой на `AGENTS.md` критически важны для исключения амнезии.

### 2.4. Cursor IDE
* **Точка входа:** Корневой файл `.cursorrules` (или `.cursor/rules/`).
* **Особенности рантайма:**
  * Фоновое индексирование кодовой базы через эмбеддинги.
  * Функция Shadow Workspace / Agent mode. Чувствителен к размеру правил, поэтому файл должен содержать прямые императивные запреты.

### 2.5. Windsurf IDE (Codeium)
* **Точка входа:** Корневой файл `.windsurfrules`.
* **Особенности рантайма:**
  * Архитектура Cascade (сочетание чата и автономного агента).
  * Отличная поддержка контекстных ссылок и терминальных команд.

### 2.6. GitHub Copilot
* **Точка входа:** `.github/copilot-instructions.md`.
* **Особенности рантайма:**
  * Считывается расширением Copilot Chat в VS Code и JetBrains для каждого запроса `@workspace`.

### 2.7. Continue.dev & Aider
* **Точка входа:** `.continue/config.json`, `.aider.conf.yml`.
* **Особенности рантайма:**
  * Фокус на 100% приватности и работе с локальными моделями через Ollama (Qwen 2.5 Coder, DeepSeek).
  * Aider автоматически формирует компактную карту репозитория (repo-map) на базе ctags/Tree-sitter и делает коммиты в Git.

## 3. Анализ семейств моделей (LLM Landscape)

### 3.1. Qwen 2.5 Coder (32B / 14B / 7B) — Флагман открытого кода
* **Разработчик:** Alibaba Cloud.
* **Лицензия:** Открытая (Apache 2.0).
* **Сильные стороны:**
  * **Лидер среди открытых моделей:** На бенчмарках HumanEval, EvalPlus, MultiPL-E и Aider Benchmark модель Qwen 2.5 Coder 32B превосходит многие проприетарные модели (включая GPT-4o-mini и Claude 3.5 Haiku) и вплотную приближается к Claude 3.5 Sonnet.
  * **Приватность данных (Air-gapped):** Модель может быть развернута на локальном GPU (RTX 3090/4090 для 32B с квантованием 4-bit, или на любом CPU/Mac для 7B/14B) через Ollama / vLLM. Исходный код предприятия никогда не покидает локальную сеть.
  * **Контекстное окно:** Нативная поддержка контекста до 128K токенов.
  * **Многоязычность:** Прекрасно понимает и генерирует текст на русском и английском языках, не теряя техническую терминологию.
* **Особенности и нюансы:**
  * При квантовании Q4_K_M локальная модель требует предельно ясных и однозначных инструкций. Наш 3-режимный подход с контрактами `[NEW]`/`[MODIFY]` и готовыми шаблонами полностью снимает риск галлюцинаций у Qwen.

### 3.2. DeepSeek (R1 / V3) — Революция рассуждений (CoT)
* **Разработчик:** DeepSeek AI.
* **Архитектура:** MoE (Multi-head Latent Attention, DeepSeekMoE).
* **Сильные стороны:**
  * Модель **DeepSeek-R1** обладает беспрецедентной глубиной «цепочки рассуждений» (Chain-of-Thought). Она идеальна для **Режима 1 (Planning / RFC)**, так как детально просчитывает пограничные случаи, риски платформы и нежизнеспособные альтернативы.
  * Крайне низкая стоимость API и наличие дистиллированных версий (на базе Qwen и Llama) для локального запуска.

### 3.3. Anthropic Claude (3.5 Sonnet / 3.7 Sonnet)
* **Сильные стороны:** Золотой стандарт для сложных рефакторингов, генерации кода и аккуратного редактирования файлов по diff-блокам. Превосходное следование отрицательным инструкциям («СТРОГО ЗАПРЕЩЕНО МЕНЯТЬ КОД В РЕЖИМЕ 1»).

### 3.4. Google Gemini (1.5 Pro / 2.0 Flash & Pro)
* **Сильные стороны:** Огромное контекстное окно (до 2 000 000 токенов). Способна удерживать в контексте всю базу знаний `docs/` и всю кодовую базу одновременно без потери деталей. Нативный движок среды Google Antigravity.

### 3.5. OpenAI (GPT-4o, o1, o3-mini)
* **Сильные стороны:** Высокая скорость, строгий JSON/Structured Output, сильное абстрактное мышление.

## 5. Исследование языковой политики (Language Standard)

### Анализ поведения моделей
При отсутствии явного языкового регламента в правилах:
1. Англоязычные модели (Claude, GPT, Qwen) по умолчанию ориентируются на язык системного файла правил (`AGENTS.md`). Если он на английском — агент начинает отвечать на английском, даже если в проекте русскоязычные документы.
2. Попытка перевести имена переменных, типов или git-коммиты на русский язык приводит к нечитаемому коду (антипаттерн «Русификация идентификаторов»).

### Решение
Внедрение параметризованного языкового правила (`doc_lang`) во все генераторы правил:
```markdown
## 🌐 Language & Terminology Standard
- **Documentation & Dialogue:** All user communications, explanations, CoT reasoning, planning (Mode 1), specs (Mode 2), bugs, and Devlog entries MUST be written in **{Language}** (e.g. Russian).
- **Code & Identifiers:** All source code, symbol names, variables, API contracts, tests, and Git commit messages remain strictly in **English**.
```

## 6. Отвергнутые подходы («Кладбище идей»)

* ❌ **Отказ от жесткой привязки к единственной среде:** Попытка поддерживать только Cline или только Cursor была отвергнута. Разработчики в одной команде используют разные IDE, поэтому инсталлятор обязан генерировать универсальный стандарт (`AGENTS.md`) и адаптеры под все популярные среды.
* ❌ **Отказ от принудительного перевода базы знаний на английский:** Попытка заставить всех вести базу знаний только на английском отвергнута. Для русскоязычных команд ведение планов и ТЗ на русском языке кардинально повышает скорость и точность формулировок, а инсталлятор должен позволять выбрать язык (`ru`, `en`, custom) через флаг `--doc-lang`.
* ❌ **Отказ от игнорирования открытых моделей (Qwen, DeepSeek):** Предложение ориентироваться только на облачные API Claude/OpenAI отвергнуто. Открытые модели достигли паритета по качеству, и архитектура Docs-as-Code должна одинаково эффективно направлять как Claude 3.7, так и локальный Qwen 2.5 Coder.

## 7. Выводы и рекомендации для инсталлятора `install.py`

1. Добавить CLI-параметр `--doc-lang` (по умолчанию `ru`).
2. В интерактивном мастере (TUI) задавать вопрос о языке на английском языке первым пунктом.
3. Добавить генерацию `GEMINI.md` для поддержки Google Antigravity и Gemini CLI.
4. Добавить поддержку сред Windsurf (`.windsurfrules`) и расширенного списка агентов в выбор визарда.
5. Интегрировать 12 канонических дисциплин `remote_notification` во все генераторы правил.
