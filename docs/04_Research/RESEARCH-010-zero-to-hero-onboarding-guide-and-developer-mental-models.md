## 1. Контекст, проблема и проверяемые гипотезы

### 1.1. Контекст
В методологии Docs-as-Code уже разработаны фундаментальные компоненты:
* Строгий 4-этапный жизненный цикл (Режим 0 Discovery ➔ Режим 1 План ➔ Режим 2 ТЗ ➔ Режим 3 Код).
* Самодостаточный инсталлятор `install.py` с поддержкой Brownfield-проектов и Greenfield-старта от сырой идеи (ADR-0014).
* Инфраструктура Obsidian Graph, 13 канонических шаблонов, утилиты `kb_lint.py` и `kb_release.py`.
* Краткий онбординг для агентов и опытных инженеров (`docs/Onboarding.md`).

Однако в Icebox дорожной карты зафиксирована задача:  
*«💡 Гайд для начинающих в агентном программировании (Zero-to-Hero Onboarding)»*.

### 1.2. Проблема
Разработчики, впервые переходящие от классического кодинга или от примитивного чата с веб-интерфейсами (ChatGPT, Claude web) к автономным AI-агентам в IDE/терминале, испытывают **когнитивный диссонанс ментальных моделей**:
1. **Иллюзия «Всемогущей одной кнопки» (Vibe Coding Fallacy):** Новичок ожидает, что напишет агенту: *«Сделай мне маркетплейс»*, агент сгенерирует 3000 строк спагетти-кода без тестов и структуры, код сломается на шаге 3, а контекст развалится. После этого наступает разочарование в инструментах.
2. **Непонимание роли базы знаний (External Long-Term Memory):** Новичок воспринимает папку `docs/` как «лишнюю бюрократию», не понимая, что файлы Markdown с викиссылками — это **единственный надежный способ удержания архитектурного фокуса LLM-агента** за пределами лимитов рабочего окна контекста.
3. **Страх перед терминалом и средой (Tooling Friction):** Непонимание, чем отличается запуск curl-команды в терминале от прямого обращения к агенту на естественном языке в чате Antigravity, Cursor или Windsurf.

### 1.3. Проверяемые гипотезы
* **Гипотеза 1 (Ментальная модель Senior Partner):** Гайд должен начинаться не со синтаксиса команд, а с фундаментальной смены роли: агент — не джуниор-копипастер и не оракул, а исполнительный Senior Partner с неограниченной скоростью печати, требующий жестких контрактов и архитектурных рамок.
* **Гипотеза 2 (Сценарии первых 15 минут — "First 15 Minutes Flow"):** Руководство должно содержать 3 пошаговых сценария «под ключ» с готовыми сниппетами промптов:
  - *Сценарий A (Greenfield):* пустая папка, только идея в голове ➔ Режим 0 (`/kb-research`).
  - *Сценарий B (Brownfield):* существующий репозиторий с кодом ➔ автодетект стека ➔ первичное планирование.
  - *Сценарий C (Hotfix):* баг в продакшене ➔ TDD регрессионный тест ➔ закрытие через `/kb-bug`.
* **Гипотеза 3 (Книга рецептов промптов — Prompt Cookbook):** Вместо абстрактных советов нужны точные шаблоны диалогов: как инициировать сессию, как заставить агента критиковать идею, как остановить галлюцинацию кода в режиме планирования.
* **Гипотеза 4 (Каталог типовых ошибок новичка — Anti-Pattern Gallery):** Явный разбор 5 главных ошибок начинающего инженера (пропуск исследования, затирание истории, ручные правки пермалинков).

## 2. Архитектурная декомпозиция структуры руководства

### Раздел 1: Фундамент и смена парадигмы (The Mental Shift)
* **От «Копипаста из браузера» к «Docs-as-Code»:** Почему чат без базы знаний обречен на забывание через 15 сообщений.
* **База знаний как RAM и SSD агента:**
  - Промпт сессии = оперативная память (RAM, быстро переполняется).
  - Папка `docs/` в Markdown = постоянный диск (SSD), откуда агент считывает контракты по требованию через викиссылки `[[...]]`.
* **Принцип 4 режимов (Double Diamond):** Почему запрет на код в Режиме 1 спасает проект от переписывания.

### Раздел 2: Матрица сред разработки (Where Do I Type This?)
Подробная, иллюстрированная шпаргалка по средам:

| Среда | Как развернуть харнесс | Как общаться с агентом | Особенности |
| :--- | :--- | :--- | :--- |
| **Antigravity / Gemini CLI** | Написать в чат: *«Установи харнесс...»* или `irm ...` в терминале | Чат Antigravity / встроенные слеш-команды | Нативная поддержка скиллов `.agents/skills/` |
| **Cursor (IDE)** | Открыть терминал (`Ctrl+~`), вставить curl-команду | Cursor Composer (`Cmd+I`) / Chat (`Cmd+L`) | Правила в `.cursorrules` подхватываются автоматически |
| **Windsurf (IDE)** | Терминал IDE или через Cascade Chat | Cascade (`Cmd+L`) | Читает `.windsurfrules` |
| **VS Code + Cline / Roo** | Терминал VS Code | Окно Cline в боковой панели | Читает `.clinerules` |
| **Claude Code (CLI)** | Запустить в терминале папку проекта | Прямой CLI-диалог | Читает `CLAUDE.md` |
| **Obsidian (Визуализация)** | Открыть как Vault папку `docs/` | Просмотр графа (`Ctrl+G`), канбана и заметок | 7 цветовых групп графа из `.obsidian/graph.json` |

### Раздел 3: Первые 15 минут — 3 пошаговых сценария

#### Сценарий 1: «У меня только идея и пустая папка» (Greenfield Idea-First)
1. Создать пустую папку: `mkdir my-cool-tool && cd my-cool-tool`.
2. В терминале или в чате агента:
   `irm https://raw.githubusercontent.com/koudinie101-png/agent-docs-harness/main/install.py | python -`
   Выбрать пункт `6) 💡 Undecided / Idea-First`.
3. Написать агенту первый промпт:
   > *«Привет! Я хочу разработать легковесный сервис синхронизации локальных заметок. Прочитай AGENTS.md и давай запустим Режим 0: /kb-research notes-sync-architecture. Проанализируй платформы, сравни Rust, Go и Python и помоги выбрать стек».*
4. Агент проводит стресс-тест, создает `RESEARCH-001`, фиксирует `ADR-0001` и наполняет `SPEC.md`!

#### Сценарий 2: «У меня уже есть рабочий проект» (Brownfield)
1. Открыть существующий проект.
2. Запустить `install.py`. Инсталлятор автоматически определит стек (например, TypeScript / Node.js) и добавит харнесс, не трогая исходный код.
3. Первый промпт агенту:
   > *«Прочитай AGENTS.md, изучи кодовую базу и заполни раздел архитектуры в SPEC.md. После этого перейдем к /kb-plan для первой фичи».*

#### Сценарий 3: «Срочный баг» (Hotfix / Defect)
1. Промпт агенту:
   > *«У нас ошибка: при передаче пустого токена сервис падает с Panic. Запусти /kb-bug empty-token-panic, проведи Root Cause Analysis и напиши падающий тест по TDD перед исправлением».*
2. Агент создает `BUG-001`, пишет тест, воспроизводит падение, исправляет код и доказывает успех тестом.

### Раздел 4: Поваренная книга диалогов (Copy-Paste Prompts Cookbook)
* **Промпт активации сессии:** *«Прочитай SPEC.md, AGENTS.md и Kanban.md. Какая задача сейчас в приоритете?»*
* **Промпт вызова критического мышления:** *«Я хочу добавить websockets. Выступи в роли критического архитектора: найди 3 причины, почему это оверинжиниринг, и предложи альтернативу»*.
* **Промпт удержания дисциплины:** *«Стоп. Мы сейчас в Режиме 1 (Планирование). Запрещено писать код. Давай сначала согласуем список затронутых файлов и тест-план»*.
* **Промпт завершения работы:** *«Код написан, тесты зеленые. Запусти /kb-complete, обнови канбан, заполни Devlog и сделай git push»*.

### Раздел 5: Главные грабли новичка (Anti-Pattern Gallery)
1. ❌ **«Кодинг в лоб без плана»** ➔ Контекст забывается, архитектура превращается в кашу.
2. ❌ **«Ручное перетаскивание файлов ТЗ в папку Done»** ➔ Ломаются пермалинки `[[TASK-XXX]]` во всех документах. Статус меняется только в frontmatter и канбане!
3. ❌ **«Фикс бага без теста»** ➔ Баг вернется через 2 недели в следующем рефакторинге.
4. ❌ **«Молчаливое согласие с агентом»** ➔ Агент предлагает сложную библиотеку вместо 10 строк на стандартной библиотеке.

## 3. Сравнительный анализ форматов размещения гайда

| Критерий | Вариант А: Огромный раздел внутри `README.md` | Вариант Б: Отдельный документ `docs/Zero_To_Hero_Guide.md` (Выбранный) | Вариант В: Внешний сайт на VitePress / Docusaurus |
| :--- | :--- | :--- | :--- |
| **Доступность оффлайн** | 🟢 Полная | 🟢 Полная (прямо в репозитории и Obsidian) | 🔴 Требует браузера и хостинга |
| **Компактность README** | 🔴 Раздувает витрину до 20 КБ | 🟢 README остается чистой витриной | 🟢 Чистый README |
| **Навигация в Obsidian** | 🟡 Сплошной текст | 🟢 Полноценный узел базы знаний с викиссылками | 🔴 Вне графа Obsidian |
| **Токеновый налог агента** | 🔴 Читается на каждом шаге | 🟢 On-Demand (агент читает только при запросе помощи) | 🟢 0 токенов |

## 4. Отвергнутые варианты

* ❌ **Интерактивный видеокурс или внешняя вики:**  
  *Причина отказа:* Нарушает канон Docs-as-Code и автономности репозитория. Знания должны храниться рядом с кодом в версионируемом Markdown-формате.
* ❌ **Размещение текста гайда в системных правилах `AGENTS.md`:**  
  *Причина отказа:* Грубое нарушение ADR-0009 (High-SNR). Обучающие материалы для людей не должны сжигать токены агента на каждом диалоговом запросе.
