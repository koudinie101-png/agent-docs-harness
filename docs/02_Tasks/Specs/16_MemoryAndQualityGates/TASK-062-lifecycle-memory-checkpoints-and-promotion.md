## 1. Цель задачи

Интегрировать контур процедурной памяти `docs/06_Memory/patterns.md` в операционный жизненный цикл разработки:
* Закрепить контрольную точку **Memory-First** в скилле `/kb-implement` (Режим 3): обязательное чтение индекса паттернов перед началом генерации кода для предотвращения наступания на известные грабли.
* Закрепить контрольную точку **Defect Loop Reflection** в скилле `/kb-complete`: обязательная рефлексия сессии разработки перед завершением задачи; фиксация инцидента в `docs/06_Memory/Incidents/` при выявлении процедурных сбоев и обновление `patterns.md`.
* Формализовать правила **двухосевого промоушена** знаний (по частоте/тяжести и по охвату применения).

## 3. Детали реализации

### 3.1. Обновление `.agents/skills/kb-implement/SKILL.md`
В раздел `## Procedure` перед шагом 1 («Read Spec») добавляется обязательный префлайт-шаг:
```markdown
0. **Memory-First Check:**
   - Если существует `docs/06_Memory/patterns.md`, ознакомиться с активными паттернами.
   - Проверить, содержит ли текущая задача риски из списка граблей (Windows paths, ложные моки, несовместимость версий, галлюцинации API).
   - Учесть защитные правила паттернов при проектировании решения.
```

### 3.2. Обновление `.agents/skills/kb-complete/SKILL.md`
В раздел `## Completion Checklist` перед финальным коммитом и `Stop & Yield` добавляется шаг:
```markdown
6. **Defect Loop Reflection (Контур самообучения):**
   - Проанализировать ход сессии: были ли допущены процедурные ошибки, падения тестов по непредвиденным причинам, ложные предположения или платформенные сбои?
   - Если ошибка выявлена:
     - Оформить краткий инцидент `docs/06_Memory/Incidents/INC-XXX-<slug>.md` по шаблону `TEMPLATE_INCIDENT.md`.
     - Если ошибка повторяется ($\text{count} \ge 2$) или критична ($\text{severity} = \text{high}$): обновить `docs/06_Memory/patterns.md` (с соблюдением лимита $\le 15$).
     - Если критично для всего проекта: вынести правило в автотест (Tier 1) или `AGENTS.md` (Tier 2).
   - Если сессия прошла чисто: зафиксировать отсутствие инцидентов.
```

### 3.3. Протокол двухосевого промоушена (Promotion Rules)
В тело скиллов и документацию вносится строгий алгоритм:
1. **Ось 1 (Уровень / Частота и тяжесть):**
   * *Уровень 0 (Сырье):* Локальный инцидент `INC-XXX` в `Incidents/`.
   * *Уровень 1 (Активный паттерн):* При $\text{count} \ge 2$ или $\text{severity} = \text{high}$ запись добавляется в `patterns.md`. При достижении 15 записей вытесняется наименее частотный паттерн.
2. **Ось 2 (Охват / Переносимость):**
   * *Охват 1 (Задача):* Специфично для единичной задачи $\to$ остается в `INC-XXX`.
   * *Охват 2 (Проект):* Повторяется в кодовой базе проекта $\to$ попадает в `patterns.md`.
   * *Охват 3 (Платформа/Стек):* Воспроизводится в любом проекте данного стека $\to$ превращается в регрессионный тест (Tier 1) или нормативный инвариант `AGENTS.md` (Tier 2).
