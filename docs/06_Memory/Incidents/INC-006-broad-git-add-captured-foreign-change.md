# ⚠️ Инцидент: INC-006 — Broad `git add -A` captured a foreign in-flight change

> **Тег:** #memory #incident | **Тяжесть:** medium | **Статус:** active  
> **Паттерн в базе:** `TRG-06` | **Задачи:** `TASK-105` (где произошло), `TASK-106` (где принято)

---

## 1. Контекст и симптом

При завершении `TASK-105` коммит был сделан командой `git add -A` (стадирование всего рабочего дерева). В коммит попал `rules/AGENTS_CORE.md` с новым правилом `PLAIN-LANGUAGE`, которое правил **не я**, а параллельная сессия. Сгенерированные артефакты (`AGENTS.md` и бандл `install.py`) при этом оставались от предыдущей версии.

Симптом: на основной ветке проверка `python scripts/gen_rules.py --check` стала падать — правило есть в корпусе, но отсутствует в сгенерированном `AGENTS.md`, то есть CI-гейт красный.

## 2. Причина (RCA)

* Две сессии работали в **одном** рабочем дереве; чужая правка была завершена, но не закоммичена.
* `git add -A` стадирует все изменённые пути, включая файлы, которых я не касался: неявное согласие на чужую работу.
* Усиливающий фактор: `git pull --rebase` не выполнился из-за грязного дерева — сигнал был замечен, но проигнорирован.

## 3. Исправление

* Из HEAD убрана только чужая часть (`96d3021`), рабочая копия второй сессии сохранена в рабочем дереве без изменений.
* Изменение принято формально через `TASK-106`: ADR-0033, тест свежести бандла, пере-базирование бюджета и коммит с **явным перечислением путей**.

## 4. Профилактика

* Никогда не использовать `git add -A` в общем рабочем дереве: только явный список путей.
* Перед коммитом сверять `git status` с тем, что действительно правил; незнакомые файлы — повод остановиться и спросить.
* Tier 1: `test_36_task_106_installed_rules_contain_plain_language` ловит дрейф «корпус обновили — бандл отстал» на уровне установленной копии.
